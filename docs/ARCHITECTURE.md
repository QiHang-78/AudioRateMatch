# 原理与兼容边界

AudioRateMatch 的目标是根据可靠的播放证据，调整选定 macOS 输出设备的采样率。它通过 Core Audio 修改真实的设备属性，不依赖模拟点击“音频 MIDI 设置”。

## 数据流

```text
Core Audio 进程、设备、输出状态 ───────────┐
                                        ▼
系统音频日志 → 格式 / 播放队列事件 → 按进程隔离的播放证据
                                        ▼
                              来源选择与设备路由检查
                                        ▼
                              稳定等待与设备切换节流
                                        ▼
                        写入设备采样率 → 系统 / 硬件回读
```

| 文件 | 职责 |
| --- | --- |
| `AudioHardware.swift` | 枚举输出设备和音频客户端，读取属性，验证能力与独占状态，写入采样率 |
| `PlaybackEvidence.swift` | 解析合成 / 实际事件，维护进程及队列状态，选择来源并决定是否允许切换 |
| `LogMonitor.swift` | 启动筛选后的系统日志流，加载历史事件并合并实时事件 |
| `MatchEngine.swift` | 连接证据与硬件，管理状态、切换及异步验证 |
| `MenuApp.swift` | 菜单栏、设备 / 应用选择和状态窗口 |
| `AppInfo.swift` | 从应用 Bundle 读取版本和标识 |
| `main.swift` | GUI 与 CLI 入口 |

## 1. 检测音频进程

通过 `kAudioHardwarePropertyProcessObjectList` 枚举 Core Audio 客户端，再读取进程 PID、输出运行状态和关联的设备。身份包含音频对象 ID、进程启动时间和可执行文件路径，用于隔离 PID 重用及旧事件。

“正在输出”表示音频 I/O 活跃，不等于有可听见的声音。有些应用即使静音或没有明显播放也会维持输出流。

应用选择使用 bundle ID 或可执行文件路径；共享 WebKit helper 的标识还包含进程名称。浏览器内部多个标签页或同一应用内多个音源不保证可以分别选择。

## 2. 取得播放证据

`/usr/bin/log stream` 读取 `com.apple.coreaudio` 子系统中与队列格式、开始和停止有关的事件。启动时另外读取最近两小时相关日志，按时间合并实时缓存。历史读取设有超时；无法取得历史格式时，需要等待新的有效播放事件。

解析器只接受具有明确队列标识的 Audio Queue 格式与活动记录。创建下一首歌的队列属于预加载，只有对应队列开始播放才参与决策。

这些内部日志字符串不是稳定的公开播放元数据接口。事件缺失、隐私隐藏、系统升级或日志格式变化可能使识别失败。没有识别到源格式时保持当前设置。

## 3. 处理路由与冲突

- 证据必须属于当前进程身份，并指向选定设备。
- 一个应用有多个活跃队列时，需要相关队列都可确认且采样率一致。
- 自动模式要求选定设备上所有相关活跃进程的格式一致；路由未知或格式未知也会阻止自动切换。
- 指定应用模式只跟随该应用，不会在它停止后自动改跟其他应用。
- 不同设备上的音频不触发当前设备切换。

## 4. 修改设备并验证

播放证据稳定约 0.65 秒后，检查设备是否支持该采样率、属性是否可写及是否被其他进程独占，然后写入 `kAudioDevicePropertyNominalSampleRate`。

正常自动检测中，每个设备在 15 秒内最多记录 5 次成功提交的写入；应用或目标采样率变化共用这份计数。手动“重新检测”会重置状态和计数，CLI `--set` 属于直接写入路径。

写入后异步回读 nominal sample rate 和所有输出流的 `kAudioStreamPropertyPhysicalFormat`。二者都匹配才显示成功。这里的“硬件回读”是 Core Audio 驱动报告的物理流格式，不是外接测量仪对 DAC 时钟的独立测量。

## 无法保证的行为

Core Audio 进程属性提供进程与 I/O 状态，不提供每个应用内部原始文件的采样率。本项目不会把设备格式或转换后格式当成原始音源格式。

如果应用先将 96 kHz 文件转换成 44.1 kHz，再以 44.1 kHz 交给系统，本工具最多只能观察交付出来的格式。将设备改为 96 kHz 无法恢复转换前的信息。同样，播放器显示“Hi-Res”不构成当前播放流是 96 kHz 的充分证据。

没有可靠 Audio Queue 证据的 Audio Unit / AVAudioEngine、浏览器、游戏、会议或 DRM 路径会保持现状。支持一种应用的一条播放路径，不表示支持该应用的所有音质档位、在线 / 本地模式及版本。

系统同时混合多个应用时，每台设备仍只能使用一套采样率。应用音效、音量、混音和系统转换都可能改变信号，采样率匹配并不等同于 bit-perfect。

## 开发参考

[Apple AudioHardwareProcess 文档](https://developer.apple.com/documentation/coreaudio/audiohardwareprocess) 和安装的 macOS SDK 中的 `CoreAudio.framework/Headers/AudioHardware.h` 可用于核对进程及设备属性。运行 `xcrun --sdk macosx --show-sdk-path` 可定位本机 SDK。日志解析的具体假设见源文件与合成测试，不将日志字符串视为 Apple 的兼容承诺。
