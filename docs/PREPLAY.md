# 播放前匹配

1.1.0 默认开启“播放前匹配（缓冲 1 秒）”。目标是在新歌声音送到 DAC 之前完成采样率切换，把硬件重新锁定的等待放在曲目开头。不同采样率换曲仍可能有等待，不承诺无缝衔接。

## 音频路径

Core Audio 的设备级 Process Tap 捕获选定输出设备的音频，排除 AudioRateMatch 自身。私有聚合设备同时包含这个 Tap 和物理输出，以物理设备为主时钟。一个 IOProc 读取捕获音频，经过约 1 秒的 C11 PCM 缓冲，再送回输出；不安装 HAL 虚拟声卡驱动，不更改系统默认输出。

捕获与输出使用同一设备时钟，避免两个独立时钟之间的缓冲追赶。当前仅支持原生采样率的 Float32 立体声；不符合条件时拒绝建立路径。音频回调内不分配内存、不读文件、不控制设备；闸门与计数通过 C11 原子变量交换。

Tap 使用 `mutedWhenTapped`，只在捕获运行期间静音原输出，避免叠加两份声音。停止或捕获失败时销毁 IOProc、聚合设备和 Tap，恢复系统直通。源进程退出、输出断开、外部改变采样率或日志监听停止时取消切换。启动后在已知来源输出期间持续收不到非零 PCM，会停止捕获并提示检查权限。

## 一次跨采样率换曲

1. 同时确认系统播放状态中的新歌、当前进程身份、设备路由和相应 Audio Queue 起播 / 格式记录。初次取得正在播放的内容不视为新歌；暂停后继续播放同一首歌也不视为新歌。
2. 只接受不超过 0.8 秒的起播通知。在 1 秒延迟中按事件时间设置闸门，并保留 40 ms 调度余量；歌头已经越过闸门时放弃此次硬件切换。
3. 向当前播放器发送暂停，等待状态确认。旧曲尾部可以继续排出，闸门前的样本排完后输出静音。未确认暂停或发生溢出时取消。
4. 销毁旧采样率音频路径，检查设备 UID、支持范围、属性可写及独占状态，再写入目标采样率。
5. 回读系统和所有物理输出流，重新建立目标采样率的缓冲。聚合输出以物理设备为主时钟，即使播放器暂停也立即启动。读取该运行输出的 host/sample 时间，要求时钟单调、有效速率偏差小于 1%，并连续稳定至少 0.5 秒；不是只等待固定时间或只看 nominal 属性。时钟来自驱动报告，不是 DAC 模拟端的独立测量。
6. 清掉设备切换期间的旧 PCM，等待音频回调确认重置，再向同一播放器发送回到歌头和播放命令。QQ 音乐可能在跳转时自行播放，因此跳转只允许发生在 DAC 就绪之后。
7. 确认播放器产生新起播记录且格式正确。任何等待都有超时；设备写入后的失败会保持播放器暂停，恢复直通，供用户手动播放。

所有耗时设备操作、暂停确认、时钟等待都在串行工作队列中执行。主界面与实时音频回调不等待这些操作。用户换歌、改变设备、停用或退出会使旧任务失效；不补发迟到的跳转或播放。设备切换前与等待时钟时都要求播放器仍为暂停状态；检测到用户主动恢复播放时取消操作并恢复直通，不再次暂停或跳回歌头。

流程中断后显示原因并保持直通；点击“重新检测”可重新建立播放缓冲。

## 适用边界

| 条件 | 行为 |
| --- | --- |
| 新歌与 DAC 采样率一致 | 保持现有路径，不暂停、跳转或重建 Tap |
| 新歌格式可信、通知及时、播放器可控制、输出无其他活跃来源 | 尝试上述播放前匹配 |
| 通知过迟、初次接管、歌曲中途继续、不支持控制、缺少曲目标识 | 保持 DAC 设置，等待下一次可确认的新歌 |
| 同一设备还有其他进程输出 | 暂缓提前切换，即使设置了优先跟随应用 |
| 缺少系统音频录制权限或音频格式不支持 | 恢复直通，显示错误；授权 / 修改后点“重新检测” |
| 关闭播放前匹配 | 停止捕获，恢复原来的 0.65 秒稳定检测与播放中直接切换 |

全应用检测仍适用，但不等于所有软件都支持暂停、跳转和可靠源格式。没有这些接口的应用不能承诺自动提前切换。软件已经内部重采样的内容也无法还原。视频、游戏、会议等选定设备上的声音同样受到约 1 秒延迟影响，可关闭此模式。

## 播放控制和隐私

系统正在播放信息通过随包构建的 mediaremote-adapter 读取；使用 Apple 自带 Perl 进程承载框架，兼容部分新版 macOS 的 MediaRemote 访问限制。只接受完整 `type=data, diff=false, payload=…` 事件。控制前检查曲目、应用和 PID；原生帮助程序在发送全局命令前再次核对当前播放器 PID。MediaRemote 是私有接口，系统更新可能使控制失效。

缓冲音频仅在进程内存中处理，不录成音频文件，不上传。系统可能要求授予“系统音频录制”权限。诊断记录采样率、缓冲计数、通知延迟和错误，不记录歌曲名、PCM 或完整 Now Playing 元数据。

## 组件与本地改动

- [CoreAudioTapKit](https://github.com/CJStanfield/CoreAudioTapKit)，MIT。固定版本见 `Vendor/CoreAudioTapKit/UPSTREAM.md`。本地去除独立包导入修饰以随应用编译，修改日志 / 聚合设备名称，使用 `mutedWhenTapped`，要求能排除自身进程，验证原生 Float32 立体声格式与聚合设备存活。聚合输出立即启动，并提供带有效标志的运行时间查询。渲染闭包固定捕获输入流数并持有渲染对象，避免回调中的弱引用操作；会话在所有退出路径中显式停止 IOProc，解除循环引用。
- [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter)，BSD-3-Clause。固定版本见 `Vendor/mediaremote-adapter/UPSTREAM.md`。本地在 `send` 和 `seek` 前加入预期播放器 PID 的二次检查；构建脚本生成与主程序相同架构的框架，并随应用附带许可证。

参考 [Apple Core Audio Taps 示例](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。本项目采用 MIT / BSD 源码；没有并入其他 GPL 采样率工具的实现。

测试与实际设备覆盖见[验证记录](VALIDATION.md)。
