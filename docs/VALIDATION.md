# 验证记录

## 1.1.0 播放前匹配验证

日期：2026-11-03。环境：Apple Silicon、macOS 27.2、QQ 音乐 11.7.0（73272）、USB Shanling H5。使用自行生成的低音量、30 秒立体声 WAV 片段，分别为 44.1、48 和 96 kHz。测试文件、实际日志、歌曲元数据和本机设备标识不随仓库发布。

`bash test.sh` 的 82 项断言通过，涵盖播放证据、路由、起播时限、播放器身份、新歌与中途恢复、单一输出来源和单调时钟。C 缓冲通过 AddressSanitizer / UndefinedBehaviorSanitizer 检查：七种采样率的逐帧立体声延迟、不同块长、迟到通知后的歌头闸门、长时间保持时的溢出静音、清空旧 PCM 和首帧脉冲位置均通过。Universal 主程序和控制框架均包含 arm64 / x86_64，并通过严格代码签名校验；这不代表已在 Intel 硬件上试听。

实测先确认 QQ 音乐确实向 H5 输出，并关闭测试环境中另一个远程音频来源。同一设备有其他进程输出时会暂缓提前切换；指定 QQ 音乐优先不能绕过这项保护。随后建立约 1 秒缓冲，并在新歌起播时执行暂停、闸门、设备切换、运行时钟验证、缓冲重置及歌头恢复。

| 新歌 / 设备切换 | 系统设置与物理流回读 | 播放器恢复 | 从打开片段至匹配确认 |
| --- | --- | --- | --- |
| 96 → 44.1 kHz | 均为 44,100 Hz | 自动从歌头恢复并确认新起播 | 约 3.9 秒 |
| 44.1 → 48 kHz | 均为 48,000 Hz | 自动从歌头恢复并确认新起播 | 约 3.9 秒 |
| 48 → 96 kHz | 均为 96,000 Hz | 自动从歌头恢复并确认新起播 | 约 5.0 秒 |

上述耗时包括播放器打开片段及状态更新，不是纯硬件切换时长或性能保证。时钟检查使用以 H5 为主时钟的运行聚合输出，并单独检查物理流格式；没有对模拟输出或实际硬件晶振进行外部测量。

另外通过以下控制检查：

- 在 96 kHz 连续打开另一首同采样率片段，未出现自动暂停、跳转或路径重建。
- 手动暂停后持续保持暂停，手动恢复后进度继续向前，没有自动回到歌头。QQ 音乐自身可能更换播放项标识，因此该项按实际进度和切换记录判断。
- 在跨采样率切换期间主动恢复播放，旧任务取消；随后继续播放，未补发自动暂停或回到歌头。
- 原生控制框架拒绝预期 PID 不匹配的命令，播放器状态未改变。
- 测试结束退出 CLI、拆除捕获并保持播放器暂停；系统默认输出恢复为 H5。

本次修复了两个实测问题：QQ 音乐的新歌元数据约晚于起播事件 450 ms，增加元数据稳定后的及时复查，避免 400 ms 常规轮询错过闸门窗口；暂停期间立即启动聚合输出，并在查询运行时间时请求有效的 host / sample 表示，避免错误等待时钟。

本次验证支持上述 QQ 音乐本地播放路径。不能据此承诺所有音质、网络歌曲、播放器、输出设备或 macOS 版本都支持提前匹配。没有做整条真实输出链的逐样本比较或模拟端断音测量；跨采样率换曲仍有等待，选定输出持续增加约 1 秒延迟，不承诺无缝或 bit-perfect。

## 1.0.2 播放格式日志兼容验证

日期：2026-11-02。环境：Apple Silicon、macOS 27.2、QQ 音乐 11.7.0（73272）、Shanling H5。

在 QQ 音乐正在输出时，1.0.1 的只读检测显示“格式未确认”。系统日志中同时存在完整的格式和起播事件，但格式记录使用 `AudioQueueObject@… AudioQueueObject: New output; format …`，旧解析器仅接受 `aq@…: New output; format …`，因此遗漏格式证据。记录在原有 info 级别查询中可见，无需提高日志权限或开启 debug。

先加入脱敏日志写法的回归场景，确认旧解析器失败；兼容两种前缀后，44 项合成断言全部通过。新增场景验证预加载不触发切换、不同采样率重叠时保持未知，以及旧队列停止后解析新队列。Universal 构建和严格代码签名检查通过。

修复版只读检测已识别当前 QQ 音乐播放流为 44.1 kHz。安装 1.0.2 后，在自动跟随所有应用模式下观察到系统输出从 48 切换至 44.1 kHz；独立 Core Audio 查询确认系统设置和硬件流回读均为 44.1 kHz，界面显示“已匹配”。更新后菜单栏波形图标仍可见。

本次只验证了当时 QQ 音乐的播放路径，没有新增覆盖其所有音质档位或其他应用的承诺。48 → 96 kHz 的新增队列场景属于合成测试；本次没有单独进行 96 kHz 的硬件切换测试。实际日志与个人诊断文件不随项目发布。

日期：2026-11-02。环境：Apple Silicon、macOS 27.2。38 项合成断言通过，Universal 构建及严格代码签名校验通过。

应用重启后菜单栏图标仍正常显示。应用包中的图标和 Finder 图标已核验；本机系统设置的菜单栏应用列表仍显示占位图，此处的图标刷新尚未解决。

本次修改不改变播放证据解析、设备访问或自动匹配策略。未重新进行音乐播放或采样率切换的硬件测试。

## 通用版硬件验证

日期：2026-10-29。环境：Apple Silicon、macOS 27.0.1、USB DAC（Shanling H5）；QQ 音乐 11.7.0（73272）。本节是整理前通用版的实测记录，并非本次重新运行的硬件测试。

通过独立的 Core Audio 状态查询验证系统采样率和物理输出流格式。表中“硬件流”指驱动回报的数据，不代表对 DAC 硬件的外部测量。测试音乐与私人诊断文件不随源码发布。

| 来源 / 场景 | 源格式 | 系统设置 | 硬件流回读 | 结果 |
| --- | --- | --- | --- | --- |
| `afplay` | 48,000 Hz | 48,000 Hz | 48,000 Hz | 约 1.88 秒自动匹配 |
| `afplay` | 96,000 Hz | 96,000 Hz | 96,000 Hz | 约 1.99 秒自动匹配 |
| `afplay` | 44,100 Hz | 44,100 Hz | 44,100 Hz | 约 2.00 秒自动匹配 |
| 独立 AVAudioPlayer 示例 | 48,000 Hz | 48,000 Hz | 48,000 Hz | 通过 |
| AVAudioPlayer 与 `afplay` 同时输出 | 48,000 与 96,000 Hz | 保持 48,000 Hz | 保持 48,000 Hz | 报告冲突 |
| 上述场景指定跟随 `afplay` | 96,000 Hz | 96,000 Hz | 96,000 Hz | 通过 |
| 独立 AVAudioEngine 示例 | 内部源为 44,100 Hz | 保持 96,000 Hz | 保持 96,000 Hz | 正确标记未确认 |
| QQ 音乐本地片段接续 `afplay` | 96,000 Hz | 44,100 → 96,000 Hz | 96,000 Hz | 通过 |

界面验证覆盖菜单栏、状态窗口、应用选择和没有应用输出时的等待状态。上述耗时只属于当时的设备与环境，不是性能承诺。
