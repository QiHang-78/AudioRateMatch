## 1.0 版本与图标验证

日期：2026-10-30。应用 Bundle 的两个版本字段和 CLI `--version` 均显示 `1.0`。Universal 构建成功，包含 arm64 和 x86_64；38 项合成测试通过。

应用图标包含 16–1024 像素资源，已检查 1024 像素预览、ICNS 文件结构及 `CFBundleIconFile` 配置。包内图标与源码资源一致，应用代码签名验证通过。图标生成使用系统 AppKit 和 `iconutil`，不需要第三方依赖。

本次变更集中在版本号、图标和构建资源，核心播放证据与采样率匹配策略没有变化。远程 CI 的状态可在下方链接按提交查看。

## 开源整理版本 2.0.0

整理日期：2026-10-30。构建环境：Apple Silicon、macOS 27.0.1、Apple Swift 6.4，以 Swift 5 语言模式编译，最低部署目标 macOS 14.2。

`bash test.sh` 的 38 项断言通过，涵盖预加载、交叠播放、暂停恢复、旧事件、进程身份、PID 重用、设备路由、显式来源选择、未知格式、冲突处理和切换频率限制。测试只使用合成事件，不读取本机音频日志，不修改设备。

`bash build.sh --arch universal` 已成功构建 arm64 和 x86_64 两个架构，生成的应用通过 Info.plist 与本地代码签名校验。这是 Apple Silicon 主机上的交叉编译结果，不代表已经在 Intel 硬件上运行。

将源码包解压到包含空格的独立目录后，从不同工作目录调用 `test.sh` 和 `package.sh --arch universal` 也已通过。另已检查 CLI 的 `--help`、`--version` 和无效命令退出行为，核对相对文档链接、脚本语法、CI YAML 结构及 Git 忽略规则。源码扫描未发现本机用户路径或常见凭据模式。

本次整理增加独立构建、打包及文档，并调整版本读取和 CLI 帮助；核心解析与匹配策略沿用下方已验证的通用版。远程 CI 的结果单独记录在仓库的 [Actions 页面](https://github.com/QiHang-78/AudioRateMatch/actions/workflows/ci.yml)，应按具体提交查看，不与本机硬件实测混用。

## 通用版硬件验证

日期：2026-10-29。环境：Apple Silicon、macOS 27.0.1、USB DAC（Shanling H5）；QQ 音乐 11.7.0（73272）。本节是整理前通用版的实测记录，并非本次重新运行的硬件测试。

通过独立的 Core Audio 状态查询验证系统采样率和物理输出流格式。表中“硬件流”指驱动回报的数据，不代表对 DAC 硬件的外部测量。测试音乐与私人诊断文件不随源码发布。

| 来源 / 场景 | 源格式 | 系统设置 | 硬件流回读 | 结果 |
| --- | --- | --- | --- | --- |
| `afplay` | 48,000 Hz | 48,000 Hz | 48,000 Hz | 约 1.88 秒自动匹配 |
| `afplay` | 96,000 Hz | 96,000 Hz | 96,000 Hz | 约 1.99 秒自动匹配 |
| `afplay` | 44,100 Hz | 44,100 Hz | 44,100 Hz | 约 2.00 秒自动匹配 |
| 独立 AVAudioPlayer 示例 | 48,000 Hz | 48,000 Hz | 48,000 Hz | 通过 |
| AVAudioPlayer 与 `afplay` 同时输出 | 48,000 与 96,000 Hz | 保持 48,000 Hz | 保持 48,000 Hz | 报告冲突 |
| 上述场景指定跟随 `afplay` | 96,000 Hz | 96,000 Hz | 96,000 Hz | 通过 |
| 独立 AVAudioEngine 示例 | 内部源为 44,100 Hz | 保持 96,000 Hz | 保持 96,000 Hz | 正确标记未确认 |
| QQ 音乐本地片段接续 `afplay` | 96,000 Hz | 44,100 → 96,000 Hz | 96,000 Hz | 通过 |

界面验证覆盖菜单栏、状态窗口、应用选择和没有应用输出时的等待状态。上述耗时只属于当时的设备与环境，不是性能承诺。

编译、单元检查或 CI 通过不能替代实际设备验证。提交新的兼容性结果时，请注明应用版本、macOS 版本、连接方式、源格式、系统设置和硬件流回读，区分“未识别格式”与“设备拒绝修改”。
